# MiniMax H3 LongCaster MVP plan

The implementation follows `LONGCASTER_ARCHITECTURE.md`, with proof order adjusted for the production workflow:

1. **PDD + REF2VA contract first — implemented.** Accept a patched `MODEL`, require external PDD `SIGMAS` by default, resolve MMH3 references, and use REF2VA conditioning for every card in a fixed-mode project. Validate stock REF2VA + PDD first; current PDD calls the hybrid-merged trunk untested.
2. **Backend persistence proof — passed without GPU.** Save a synthetic H3 sampler-output MMH3, restart the Python process, load and verify it, prepare the 39-frame joint AV handover, and save the continued card.
3. **Project/card state — implemented and tested.** UUID cards, explicit ancestry, atomic manifest writes, cross-process project lock, immutable accepted archives, acceptance journals, and restart reconciliation.
4. **Controller operations — implemented and tested.** Generate, Retry, Accept, Append, Resume, duration alignment, generation fingerprints, and separate decode/preview.
5. **Minimal UI/workflows — implemented.** Controller buttons, PDD REF2VA example, and standard T2VA baseline.
6. **Joined timeline export — implemented.** Stream accepted cards in timeline order to NVENC while removing each continuation prefix from video and audio.
7. **Stage 2A current-state anchors — implemented; visual A/B pending.** Decode and persist an accepted card's final frame, attach it by source-card and anchor UUID, and apply it at the next card's frame-38 handover boundary through native `MiniMaxH3AddGuide` conditioning. Preserve the raw prompt while optionally adding the minimal authoritative-state instruction to the effective prompt.
8. **Stage 2B visual identity anchor — implemented; visual A/B pending.** Select a project and accepted card, scrub its registered preview, persist the exact MMH3 frame by UUID, and add the active subject checkpoint through native REF2VA `minimax_refs` while retaining the Stage 2A guide and direct latent prefix.
9. **Stage 2C LongCaster Studio + Structured Prompt Editor — core implemented; integrated UI expansion and interactive/GPU acceptance pending.** The workspace creates and opens managed projects, exposes cards and identity history, gives recorded references prompt-style numbering with a route back to the owning graph nodes, rebuilds missing accepted previews through the existing VAE path, supports explicit continuation choice, and provides side-by-side full/section prompt editing with safe labelled-flat-prompt conversion. Complete the remaining integrated Studio scope below before Stage 2C acceptance. See `docs/stage-2c-cards-interface.md`.
10. **Stage 3A long-run drift benchmark — planned after Stage 2C.** Use repeatable 10–20+ card sequences to locate and characterize identity, state, motion, audio, and color drift before selecting another continuation method.
11. **Stage 3B Context Loop / Drift Control AV — deferred.** Integrate it as an optional continuation strategy only after the Stage 3A benchmark.
12. **Stage 3C color-stable drift control — conditional.** Add it only if the benchmark shows that color, luminance, or saturation drift remains significant.
13. **Stage 3D CLSS experimental continuation backend — deferred.** Evaluate it only after the simpler drift-control modes have measured results.
14. **Production acceptance — requires local GPU runs.** Keep the documented state and identity A/B gates. Stage 2C additionally must complete a practical 10–20+ card authoring run, restart ComfyUI, resume the project, and continue generation while checking prompt provenance, references, anchors, and AV seams.
15. **Middle-card retake — investigated, not implemented.** Use reroll plus transitive descendant invalidation as the reliable baseline. An opt-in FL2VA bridge may preserve later rendered media by constraining the replacement between its neighbors, but those descendants remain ancestry-stale and require seam review. See `docs/fl2va-middle-retake.md`.

### Stage 2C remaining integrated UI scope

Implement the remaining Studio work in this order:

1. **Persistent execution panel — implemented; interactive/GPU acceptance pending.** LongCaster Studio shows queued, running, completed, interrupted, and failed states; the current node or generation stage; live sampling progress and percentage; a bounded scrolling log; and errors or tracebacks. The panel sits below the card workspace, keeps its compact status row visible, and lets the user show or hide the fixed-height log. ComfyUI execution events drive progress, and relevant backend logger records arrive through LongCaster browser events.
2. **Stop Generation — implemented; interactive/GPU acceptance pending.** **Stop Generation / Unlock** remains in the Studio header, interrupts the active ComfyUI prompt, queues the existing LongCaster cancel action, reconciles the pending operation, and releases the project lock.
3. **Card and Project tabs — implemented; interactive acceptance pending.** Card retains prompt editing, preview, navigation, and generation actions. Project holds project-level identities and reference inspection. Execution status and Stop Generation remain visible from either tab.
4. **Per-card REF2VA reference image size — implemented; interactive acceptance pending.** Card exposes the existing `match` and `max` choices, persists the choice across reload/restart, synchronizes it to the controller before Generate/Retry, and freezes it in each retained take and recipe. Changing it after rendering marks the draft dirty and requires Retry; selecting a prior take restores its exact setting.
5. Add project-owned reference management to Project, backed by a reusable project asset library and card-level reference selections. Users must be able to upload, name, inspect, and retain picture, video, and audio assets without editing MMH3 graph nodes. Each editable card can inherit the project default selection or choose and reorder its own active references; per-media ordering defines that card's `<Picture N>`, `<Video N>`, and `<Audio N>` tokens. Reference changes after rendering mark that draft dirty and require Retry. Accepted cards retain an immutable snapshot of asset IDs, content hashes, labels, roles, ordering, and prompt-token assignments even when the project defaults or later cards change.
6. **Project identity anchors — implemented; interactive acceptance pending.** Project shows every identity's source card, selected frame, scope, label, image, and active/enabled state. It can bind, enable, disable, or clear identities and provides an accepted-card preview selector for creating another checkpoint through the existing identity node.
7. Add **Stitch as One Video** to Project. It must invoke the existing timeline exporter for accepted cards, expose export progress and errors in the execution panel, and present the completed video without requiring the user to find or enable the graph export node.

Stage 2C acceptance requires the full workflow to be operable from Studio during a practical multi-card run: monitor generation, stop safely, edit and append cards, choose and verify each REF2VA card's `match` or `max` reference sizing, manage project references and identities, and create the final stitched video. Test these controls across a ComfyUI restart and project resume.

## Temporary Stage 3A detour

**Continuation refine is implemented; GPU/workflow and long-run A/B validation remain user-run.** Studio supports synchronized Off, Auto, and Manual controls; a per-card Manual checkbox; acceptance-time refinement; post-accept generation/regeneration; unpublish cleanup; separate refine SIGMAS, sampler, seed policy, and optional model; immutable accepted masters; separately verified derivative MMH3 artifacts; joint AV prefix reconstruction and fail-closed verification; explicit accepted/refined source selection; frozen continuation lineage; and safe fallback. No CLSS, upscale, color correction, scene detection, or automatic drift detection was added.

Stage 2C remains limited to one locked generation mode after rendering begins, the existing continuation/controller paths, one automatic last-frame state anchor, structured prompt authoring, and an all-cards project view. It does not include Context Loop, Drift Control, color-stable drift, CLSS, branch editing, middle-card bridge retakes, automatic prompt writing/rewriting, or polished timeline/audio editing. Do not reorder Stages 2C–3D unless a concrete blocker requires it.
